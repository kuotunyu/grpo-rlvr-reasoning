For both model repositories:

1. Replace `README.md` with a card whose YAML declares `license: other` and
   `license_name: qwen-research`. Generate the legal section through
   `hf_release.py`; do not describe a model artifact as Apache-2.0.
2. Add `LICENSE`, byte-for-byte from
   `LICENSES/QWEN-RESEARCH-LICENSE.txt`. It is pinned to Qwen revision
   `aa8e72537993ba99e69dfaafa59ed015b17504d1` and SHA-256
   `ef52482bb785733093dc9a2e8edd8e764c77d12d8e9d8f10a80c9b547d32d0f9`.
3. Add `NOTICE`, generated by `hf_release.model_notice()`. It must contain the
   Qwen-required notice and identify the model as improved using Qwen.
4. Attribute the GSM8K evaluation material to OpenAI under MIT and cite Cobbe
   et al., *Training Verifiers to Solve Math Word Problems* (2021).
5. Describe the verifier result narrowly: it did not flag obvious invalid
   output in the inspected 200-example slice. Do not claim that reward hacking
   is impossible.
6. State that Qwen Research License use is non-commercial research/evaluation;
   commercial use needs a separate Qwen license.

The repository's Apache-2.0 statement applies only to original project code,
subject to the source-specific exceptions in `THIRD_PARTY_NOTICES.md`. It must
not be copied into model-card license metadata.

## Safe execution shape

Use one `HfApi.create_commit` call per repository with `create_pr=True` and the
reviewed head supplied as `parent_commit`. The operation list must be assembled
from explicit file paths: three additions/replacements for the merged repo, and
three additions/replacements plus exactly three deletions for the LoRA repo.
Abort if either remote head changed after this audit.

Before merging either PR:

1. inspect the rendered card and PR file diff;
2. run `hf_release.audit_hf_file_layout()` against the PR revision;
3. confirm the merged repository still exposes its index and both shards;
4. confirm the LoRA repository exposes `adapter_config.json` and
   `adapter_model.safetensors`, and exposes no `model-*.safetensors` or
   `model.safetensors.index.json`;
5. confirm the merged shard and LoRA adapter hashes remain the reviewed values;
6. confirm the eventual GitHub source link returns successfully before making
   it a live card link.

If a merged PR is wrong, close it without merging. If a merged commit later
needs reversal, create a normal revert commit. Do not rewrite repository
history or delete either repository.
